Kev とは

Kev は、Jared Palmer 氏が公開しているオープンソースの決定モデル(decision model)だ。文章を生成する言語モデルとは違い、「状態」と「質問」を受け取って、答えの候補ごとの確率を1回の計算で返す。

できること: 1つの状態に対して、Yes/No(noul)、選択肢から1つを選ぶ(choice)、段階評価(score)の質問を、まとめて答えられる。確率は較正されていて、「どれくらい自信があるか」も読み取れる。

中身: Qwen3.5(0.8B / 4B / 9B)や Qwen3.8-27B をベースに、LoRA と、選択肢を指し示す小さな読み出し部(ポインタヘッド)を学習させている。文章を1文字ずつ生成しないので、速くて安い。

このプロジェクトでの使い方: テトリスの盤面を「状態」に、置き場所の候補を「選択肢」にして、Kev-4B に1手ずつ選ばせている。さらに、Kev に付属する学習スクリプト(kev.train)で、強化学習の結果を Kev 自身に覚えさせている。

ライセンス: Apache-2.0(ベースの Qwen3.5 も Apache-2.0)。

仕組み

Kev への問いかけ

Kev は文章を生成しない決定モデルで、状態と質問を受け取ると、選択肢ごとの確率を1回の計算で返す。テトリスでは1手ごとに、次のように問いかける。

状態: 盤面のテキスト表現、現在のミノ、次のミノ(1個)、列の高さ、穴の数

質問: 置き場所の候補(回転と列の組み合わせ、30〜40通り)から1つを選ぶ。第57世代までは、各候補に置いた結果の「消えるライン数・穴・オーバーハング・最高の高さ・凸凹・最も深い井戸・テトリス準備済みの行数」を説明として付けていた。第44〜49世代で「置いた後の盤面を思い描く」推論の練習をし、第50世代から説明なしの割合を25%→50%→75%と増やし、第58世代からは練習もテストも置くマス(列:行)の座標だけを渡して、盤面の良し悪しの評価は Kev 自身にさせている。第60世代からは盤面の図を1マスずつ区切って書く(「#########」が数マス分まとめて1トークンになり、どの列が空いているか読み取りにくかったため)。「決定モデル」としての判断力そのものを育てるのが狙いだ

方針: Kev に見せるのは現在と次のミノだけ。それより先のミノや、先読みの結果は見せない。座標だけの候補のときは、指示文に「置いた後の盤面を自分で思い浮かべてから選ぶ」の一文を加えている(第50世代〜)

ゲームのルール

項目ルール1(第0〜11世代)ルール2(第12世代〜)
ミノの出現盤面の上の外側から、どの列にも降りてこられる最上段の中央に出現する(本来のテトリスと同じ)

1ミノあたりの成績はルールをまたいでも比べられるが、ルール2の方が厳しい(中央が高くなると終わる)。過去の世代の録画は、記録したときのルールで再生している。

1世代の流れ(第39世代〜)

1練習試合Kev-0.8B が2ゲームを同時に打つ(配信中のゲームを優先し、他のゲームの問いかけはその後ろに並ぶので配信は1手あたり約50〜200msを保つ)。85%は Kev の一番の手、15%は上位3候補から Kev の確率に応じて探索。積み上がりが10段を超えた局面やテトリスの準備ができた局面では探索も穴マスクもせず、ライン消しは常にマスクしない
2ロールアウトと学習練習試合のあと CPU 12プロセスで並列にロールアウトを行う(5〜7分)。局面の15%で、Kev の上位3手+先生の手を候補にし、先生の2手先読み探索が10手先まで打ち進める(候補ごとに2回)。報酬とその後の盤面の手作り評価でラベルを決め、教師ラベルより優先する(1世代あたり650〜900局面、先生と食い違うのは約45%)。残りの局面は先生の手を正解として、Kev の LoRA とポインタヘッドを追加学習する(kev.train)
3実力テストランダムなしで5ゲーム(1ゲームずつ、最初の5つは昔から同じブロック順、最大500手)。1ミノあたりの得点・ライン数、テトリス回数、生き残った手数で成績を出し、これを基準に親の世代を選ぶ。第36世代までは10ゲーム、第37・38世代は1000手上限で試した。ゲームごとのばらつき(生き残る世代で1ミノあたり±2点程度)と、500手時点と1000手時点の得点がほぼ同じことを確かめて、第39世代から5ゲーム・500手にした。第58世代からは、候補手の説明に計算済みの結果を付けずに測っている

「先生」は人間が設計した評価式で2手先まで読むプログラム。第16世代からは、Kev はこの先生の手をまねて学んでいる(模倣学習)。第37世代からは、Kev 自身のロールアウト(自分で先まで打ってみた結果)によるラベルも一部で使い、先生の評価式の上限を超えることを狙う。第15世代までは、Kev 自身が試した手を報酬で選んで学ぶ強化学習だった。

世代ごとのレポート

世代の学習が終わるたびに自動で更新される(新しい順)。

    わかったこと(第58世代時点)

    • v1(第1〜8世代): 生き残る力は大きく伸びた(第6世代で 44.1点/ミノ、5ゲーム中4ゲームが500手の上限まで生存)。ただ、ほぼ1列消しばかりだった
    • v2(第9〜11世代): テトリスを狙う報酬にすると、テトリスは増えたが、生き残りが一時落ちた
    • ルールの変更と v3・v4 前半(第12〜15世代): 本来のテトリスのルール(出現位置のゲームオーバー、SRS 回転)にすると、それまでのモデルは約80〜150手で負けるようになった。報酬を調整しても、30点/ミノ前後で頭打ちが続いた
    • 先生つき学習(第16世代〜): 2手先読みの先生の手をまねさせると一気に伸びた。1ミノあたり得点は 29 → 47 → 57 → 50 → 52 → 59.6、テトリスは 0.1 → 2.0 → 4.8 → 1.2 → 3.5 → 11.7 回/ゲーム。第19世代では10ゲームすべてが500手の上限まで生き残った
    • 効いた調整: 「穴やオーバーハングは残すほど損」「高さが半分を超えたら生き残り優先」「幅1〜3列の2本目の井戸は深いほど急に損」を先生の評価に入れると(第19世代〜)、生き残りを保ったままテトリスが増えた
    • 模倣学習の頭打りと 0.8B への切り替え(第20〜24世代): 第20世代(59.6点/ミノ)を親にした模倣学習は伸びず、第21〜22世代は50点台前半で上下した。4B 第20世代から Kev-0.8B へ蒸留(第23世代 50.4点/ミノ)、0.8B での模倣学習(第24世代 51.1点/ミノ)でも通用することを確認した
    • 0.8B での価値学習と Kev 自身の探索(第25〜36世代): 盤面の価値を5段階で学ばせ、それを使った Kev 自身の1手先読みに切り替えると、練習試合が短く崩壊した(探索の候補を上位4手から均等に選んでいたため→上位3手を Kev の確率で選ぶ方式に修正)。価値の目標を「ゲーム終了までの割引報酬」から「10手先までの報酬+10手後の盤面評価」に変えても、実際の結果との相関は 0.43 → 0.62 → 0.77 まで上がった一方、候補手どうしの比較(先生の手を選べる割合)は 54% → 44% と改善せず、値の学習では第一候補を上回る判断ができなかった。全体では 50〜56 点/ミノ前後で足踏みし(先生自身の水準である 55〜57 点/ミノに近いところ)、第37世代から価値学習を止め、Kev 自身のロールアウトによる手のラベル付けに切り替えた
    • ロールアウトへの切り替えと v5(第37〜43世代): 先生の手に加え、Kev 自身の上位3手をロールアウト(先読み)でラベル付けする方式に切り替え、報酬 v5 でテトリス狙いを一本化した。第46世代で 63.3点/ミノ・テトリス19.2回/ゲーム(全500手生存)と、それまでの最高になった
    • 「決定モデル」の目標(plan.md 5.9/5.10): 第57世代までは、候補手の説明に計算済みの結果(消えるライン数・穴・高さなど)を付けていたため、Kev はその要約を読み比べるだけで良い手を選べてしまっていた。目標を「盤面と現在・次のミノ、指示文、候補の置くマスの座標だけで、全部入り時の9割以上の実力を出す」ことに定め、計算済みの結果を段階的に外す作業を始めた
    • 盤面想像ラウンド(第44〜49世代): 候補の説明を座標だけにする代わりに、「消える行・空きマスを覆うか・高さ・テトリス準備の有無」を Kev 自身に答えさせる練習問題を追加した。学習前(第42世代)は正答率 消える行6% / 覆う65% / 高さ61% / 準備77%だったのが、第46世代で 94.3 / 78.7 / 99 / 96.7、第49世代で 93.7 / 82.3 / 99 / 96 まで上がり、伸びが3ラウンド止まったところで打ち切った
    • 離乳(第50〜58世代): 学習データを予測あり・なしの両方の形で用意し、練習試合のうち予測なしで打たせる割合を 25% → 50% → 75% → 100% と段階的に上げた。予測なし単体の実力は 第50世代 10.8点/ミノ・52手 → 第55世代 55.4点/ミノ・全500手・テトリス8.0回 まで伸びたが、第56・57世代はやや落ちて53点台で足踏みした
    • 第58世代: テストも予測なしに: 実力テストそのものを予測なし(100%)で測る形に切り替えた。結果は 54.4点/ミノ・全500手生存・テトリス3.8回/ゲーム。合格ライン(57.0点/ミノ)まで2.6点差で、足りないのは主にテトリスの回数(予測ありでは15〜19回/ゲーム)

    見直しの理由

    • v1 → v2: 1列消しばかりだったので、テトリスの価値を倍にし、高さの減点を外した(テトリスの準備では必然的に高く積むため)
    • v2 → v3: 10手以上の連携を学べるよう、評価を10手ウィンドウにした。滑り込み・回転入れを候補にし、穴とオーバーハングを分けて扱った
    • v3 → v4: 過去の事例(Dellacherie / BCTS、Cold Clear、CBMPI)を取り入れた。第16世代からは、報酬の調整だけでは伸びなかったため、2手先読みの先生の手をまねる模倣学習に切り替えた
    • v4 の途中調整: 「井戸を何本も残して天井まで積む」「2本井戸で塔が高くなる」「穴を放置する」負け方を見て、余分な井戸・積みすぎ・穴の放置を順に重く評価した
    • v4 → v5: 穴や2本目の井戸を作ったらしっかり埋め戻させたいのに、v4 では小さなライン消しでも埋め戻しが進んでしまい、テトリスに育つ前に崩れる盤面が残っていた。きれいな盤面では小さなライン消しに代償を付けてテトリスだけを組み立てさせ、穴や2本目の井戸があるときだけ通常のライン報酬で掘り出しを優先させることにした。穴・オーバーハングの罰則と2本目の井戸の重みも強めた
    • v5 の微調整(第39世代〜): 低くて穴のない盤面でも1〜2段消しが多いままだった。原因は「きれいな盤面」の判定で、深さ2の浅いくぼみまで2本目の井戸と数え「きれいでない」扱いになり、ただの1段消しにも満額の報酬が出ていたこと。低い盤面で満額が出るのを、穴・オーバーハング・埋もれた穴・2本目の井戸のいずれかを減らす消し方だけに絞った
    • 見逃したテトリスと準備の完成(第41世代〜): テトリスの準備(4段そろい)ができているのに I ミノを他所へ置く手を悪手として重く罰し(−8、3倍の重みで学習)、準備を完成させる手には加点(+4)した。準備を崩す手そのものには罰則を付けていない(崩すのが正しい場面もあるという判断による)

    高速化

    1世代に30〜55分かかっているのを縮める。今回は、Kev-4B とこれまでの学習結果(第10世代まで)をそのまま引き継ぎ、実行環境だけを入れ替える。詳しい構想は 高速化構想 にある。

    遅い原因: (1) Qwen3.5 の DeltaNet と畳み込みに使う高速化ライブラリ(flash-linear-attention、causal-conv1d)が Windows では入らず、遅い標準実装で動いている。(2) 16GB での安定性を優先して、CUDA グラフを無効にしている。(3) 1手ずつ順番に問い合わせていて、まとめ処理を使っていない。

    今回の方針: 学習ループと Kev を Docker(WSL2 の Linux コンテナ、GPU あり)に移し、高速化ライブラリを入れる。CUDA グラフは無効のまま(4B と 16GB の組み合わせでは不安定になるおそれがあるため)。配信サーバーは Windows に残し、共有フォルダでつなぐ。

    高速化レポート: 何をして、どれだけ速くなったか

    #やったことねらい効果(測定値)
    1学習ループと Kev を Docker(WSL2 の Linux コンテナ)に移したWindows では入らない高速化ライブラリを使うためライブラリなしのコンテナでも、推論はほぼ同じ(下の表の「なし」)
    2causal-conv1d を RTX 50 系(sm_120)向けにビルドして導入Qwen3.5 の短い畳み込みを高速化300 → 291 ms(約 3% 短縮)
    3flash-linear-attention を導入Qwen3.5 の DeltaNet(線形注意)を高速化300 → 223 ms(約 26% 短縮)
    42 と 3 を併用—300 → 209 ms(約 30% 短縮)
    5Kev の融合カーネル(fused_qwen35)を無効化(KEV_FUSED=0)サーバーで最初の問い合わせ時に WSL ごと落ちる問題の回避安定して動くようになった(速さへの影響なし)
    6モデルのファイルを Docker 内部の保存領域にコピーWindows のフォルダ共有からの読み込みが遅いため読み込み 約 4 分半 → 約 16 秒
    7練習試合と実力テストのゲームを8つ同時に進める(第17世代〜)Kev の推論(GPU)を待つ間に、他のゲームの通信・問いかけの作成・先読み探索・盤面の計算(CPU)を進める練習試合 約 2.9 → 約 7.5 手/秒(約 2.6 倍)。GPU 使用率 98%、VRAM 10.3GB
    —CUDA グラフは無効のまま4B と 16GB の組み合わせでの安定性を優先未適用(今後 0.8B で試す)

    2〜4 は、コンテナ内で第10世代のモデルに同じ問いかけ(空の盤面)を送り、2回目以降の推論時間を比べた値。1回目はコンパイルのため約 20 秒かかる。

    まとめ: 実際のプレイ(サーバー経由、同じゲームの同じ局面120手)では、推論が中央値 430 → 318 ms(約 26% 短縮)になった。モデルの読み込みは 約 4 分半 → 約 16 秒。学習(重みの更新)の速さは、第11世代の学習段階の結果を待って追記する。
