Kev とは

Kev は、Jared Palmer 氏が公開しているオープンソースの決定モデル(decision model)だ。文章を生成する言語モデルとは違い、「状態」と「質問」を受け取って、答えの候補ごとの確率を1回の計算で返す。

できること: 1つの状態に対して、Yes/No(noul)、選択肢から1つを選ぶ(choice)、段階評価(score)の質問を、まとめて答えられる。確率は較正されていて、「どれくらい自信があるか」も読み取れる。

中身: Qwen3.5(0.8B / 4B / 9B)や Qwen3.8-27B をベースに、LoRA と、選択肢を指し示す小さな読み出し部(ポインタヘッド)を学習させている。文章を1文字ずつ生成しないので、速くて安い。

このプロジェクトでの使い方: テトリスの盤面を「状態」に、置き場所の候補を「選択肢」にして、Kev-4B に1手ずつ選ばせている。さらに、Kev に付属する学習スクリプト(kev.train)で、強化学習の結果を Kev 自身に覚えさせている。

ライセンス: Apache-2.0(ベースの Qwen3.5 も Apache-2.0)。

仕組み

Kev への問いかけ

Kev は文章を生成しない決定モデルで、状態と質問を受け取ると、選択肢ごとの確率を1回の計算で返す。テトリスでは1手ごとに、次のように問いかける。

状態: 盤面のテキスト表現、現在のミノ、次のミノ(1個)、列の高さ、穴の数

質問: 置き場所の候補(回転と列の組み合わせ、30〜40通り)から1つを選ぶ。各候補には、置いた結果の「消えるライン数・穴・最高の高さ・凸凹・最も深い井戸」を説明として付ける

方針: Kev に見せるのは現在と次のミノだけ。それより先のミノや、先読みの結果は見せない

ゲームのルール

項目ルール1(第0〜11世代)ルール2(第12世代〜)
ミノの出現盤面の上の外側から、どの列にも降りてこられる最上段の中央に出現する(本来のテトリスと同じ)
ゲームオーバー置き場所が1つもなくなったとき出現した位置で、ブロックと重なったとき
回転形の左上を基準に回し、左右1マスだけずらして試す簡易版標準の回転システム(SRS)。回転の中心と壁蹴りの表に従い、着地後の回転や T-スピンも正しく扱う
置き場所の候補回転して真下に落とす(第12世代の v3 からは滑り込みも)出現位置から左右移動・回転・1段落下でたどり着ける場所すべて

1ミノあたりの成績はルールをまたいでも比べられるが、ルール2の方が厳しい(中央が高くなると終わる)。過去の世代の録画は、記録したときのルールで再生している。

1世代の流れ

1練習試合少しランダムに手を選んで16ゲーム遊び、プレイの記録を集める(1ゲーム最大200手)
2学習記録から予想より良かった手を選び、その手を選ぶように Kev の重み(LoRA)を調整する
3実力テストランダムなしで5ゲーム遊ぶ(毎回同じブロック順、最大500手)。平均得点をその世代の成績にする

「予想より良かった手」は、各手のあとに得た報酬の割引合計を、盤面の特徴から予想した値と比べて決める(アドバンテージ)。その上位35%を学習に使う。

    見直しの理由

    • v1 → v2: テトリスの準備では必然的に高く積むため、高さの減点を外した。テトリスの価値を倍にし、何手も先で報われる手を評価できるよう割引率を上げた。生き残る力を引き継ぐため、ゼロからではなく第6世代から分岐した
    • v2 → v3: v2 でテトリスは増えたが、生き残る手数が第10世代で大きく落ちた(第11世代で回復)。10手以上の連携を学べるよう、評価を10手ウィンドウにした。上にブロックが被った空白は、完全に塞がっていなくても避けたい。一方で、滑り込みで埋めたときや、上のラインが消えて穴でなくなったときには加点したい。解消の加点を発生の減点より小さくして、「穴を作ってから埋める」ことで点を稼げないようにする

    学習計画の変遷

    • テトリス本体と Kev 向けインターフェースを作成置き方は「回転して真下に落とす」。候補ごとに結果の説明を付けて、Choice 質問として Kev に渡す
    • 強化学習ループ(v1)練習試合 → 良かった手の学習 → 実力テスト、の3段階。直前2世代の良い手も一緒に復習する
    • 評価を平均ライン数から平均得点に変更テストの上限は、世代の比較を続けるため500手のまま
    • 止めるまで世代を重ねる運用に変更配信画面では、練習試合とテストをライブで流し、学習中は過去の世代の録画を再生する
    • 報酬 v2 に変更し、第6世代から分岐生き残りは達成したが、テトリスを狙わないことがわかったため
    • 学習時の長さの上限を拡大v2 で問いかけが長くなり、第10世代の学習が上限超過で止まったため(1024 → 1536)
    • 世代ごとの結果を GitHub Pages に自動公開世代が終わるたびに、このページの成績とレポートが更新される
    • v2 の第9・10世代テトリスは増えた(第9世代で1.6回/ゲーム)が、生き残る手数は第6世代の平均458手から240手(第10世代)まで落ちた。生存と高得点は両立できる水準なので、学習の不足と見ている
    • v2 の第11世代(コンテナで実行)1ミノあたり得点 38.4 → 40.4、平均手数 240 → 351 と、生き残りが回復した
    • ゲームのルールを本来のテトリスに合わせた(第12世代〜)最上段の中央に出現し、そこで重なったらゲームオーバー。回転は標準の SRS にし、着地後の回転も正しく扱う
    • v3 に切り替え(第12世代〜)10手ウィンドウ、滑り込み・回転入れ、穴とオーバーハングの区別、天井近くの減点、練習問題を入れ、第6世代から学習を始めた
    • 高速化のため学習を一時停止し、Docker に移行作業中は配信画面に「高速化改良中」を表示した。Kev の融合カーネルが WSL を落とす問題を切り分けて回避し、第10世代から、コンテナで学習を再開した

    今後の計画

    学習方針 v3(第12世代から実施中)

    第11世代(v2)のテスト後に v3 に切り替え、第12世代を第6世代(それまでで成績が最良)から学習している。v3 で十分に育ててから 0.8B に蒸留する。v3 で入れたのは次の内容だ。

    10手ウィンドウで評価

    各手で終わる直前10手をウィンドウとし、1手ずつずらす。ウィンドウ内の報酬と盤面の良さの変化で評価し、各手はそれを含むウィンドウの平均で選ぶ。テトリスの準備のような、10手以上の連携を学べるようにする。

    滑り込み・回転入れ

    左右移動・回転・1段落としでたどり着ける場所をすべて候補にする。オーバーハングの下へ滑り込ませる手も打てるようにする。

    穴の報酬の細分化

    塞がった穴とオーバーハングを分けて減点し、解消したら加点する。候補の説明でも2つを分けて表示する。

    生き残りの立て直し

    天井近く(上から4段以内)に積んだときだけ減点する。練習試合の打ち切りを200手から400手に延ばし、積みすぎて死ぬ場面も学べるようにする。

    練習試合での穴の回避

    穴を作らない候補がある限り、そこから選ぶ(まれに例外を許す)。くじ引きの温度を1.0から0.7に下げる。

    4段消しの練習問題と、親の選び方

    練習試合の4分の1を、井戸があり何段か準備済みの盤面から始める。直近数世代のうち、テストの成績が最も良い世代を親にする。

    v4(第14世代から実施中。後半の 1・2 はこれから)

    基本方針は、長期の戦略を立てられるようにすること。先のミノは見せない(見せるのは現在と次だけ)条件のまま、手の良し悪しを長い目で評価できるようにする。

    1. Kev 自身に盤面の良さを答えさせる

    Kev は1回の計算で複数の質問に答えられる。「この盤面はこの先どれくらい良いか」という段階評価の質問を追加して学習させる。手の評価の基準(今は盤面の特徴から計算する単純な式)を、Kev 自身の判断に置き換える。

    2. 練習試合で2手の先読み探索

    見えている「現在と次のミノ」だけを使って2手の組み合わせを1の評価で比べ、良い手を選ぶ。探索で見つけた手を Kev に覚えさせる(AlphaZero と同じ考え方)。見せる情報のルールは守れる。

    3. 名手の記録を繰り返し学ぶ

    世代をまたいで、1ミノあたりの得点が高かったゲームを保存し、その手を学習データに混ぜる。

    4. 連続テトリスへの加点

    テトリスを続けて出したときの報酬を上乗せする。ゲームの得点ルールは変えないので、過去の世代とそのまま比べられる。

    5. テストの精度を上げる

    テストを10ゲームにし、同じブロック順で前の世代と比べる。偶然の揺れで、親の世代を選び間違えないようにする。

    6. ホールド機能(要相談)

    ミノを1つ取っておける、本来のテトリスの機能。戦略の幅は広がるが、ルールが変わるので過去の世代とは比べにくくなる。

    過去の事例から v4 に取り入れること

    事例効いたものv4 での使い方
    Dellacherie / BCTS穴、置いた高さ、行遷移・列遷移、井戸の合計、浸食セル、穴の深さ、穴のある行数盤面の良さ(ポテンシャル)と、手の評価の基準に使う
    CBMPI(NeurIPS 2013)数手先まで試しに打つ方策改善。いろいろな高さの盤面から学ぶと強い2手の先読み探索、練習問題を中〜高い盤面にも広げる
    DQN の実装例報酬 = 1 + 10 × (ライン数)²。まとめ消しを強く優遇4列消しの大きな報酬を維持
    Cold Clear安全な間は1列・2列消しを減点、4列消し・T-スピン・連続テトリスを加点高さで変わる消し方の評価、連続テトリスに +8、T-スピンに加点
    報酬の整形の理論盤面の良さの差分だけを足すと、最適な方策を変えない整形はポテンシャル型に限る

    参考: The Game of Tetris in Machine Learning / CBMPI / nuno-faria/tetris-ai / Cold Clear

    v5 の案(先生つき学習が頭打ちになったら)

    局面に応じた戦い方

    低いときは井戸掘りと4段消しの準備、穴があるときは穴の解消を最優先、半分を超えたら生き残り重視。先生の評価を高さの帯で切り替え、Kev への問いかけにも今の局面を一行で伝える。

    複数手の連携

    先読みを3手目まで広げる。見えない3手目のミノは、7種類それぞれの最善手の平均で評価する。先生の一連の手を、つながりとして学習させる。

    頭打ちの目安: 1ミノあたり得点と平均手数が、2〜3世代続けて伸びない。

    0.8B への蒸留

    v3 の世代が「500手まで5ゲーム中4以上生き残る」「1ラインあたり140点以上」「テトリスが毎ゲーム数回」を満たしたら、その世代を先生にして Kev-0.8B に蒸留する。そのあとは 0.8B で、CUDA グラフと複数ゲームの同時進行を使って世代を速く回す。成績が 4B に届かない場合は 4B を使い続ける。

    高速化(推論は完了、学習は測定中)

    1世代に30〜55分かかっているのを縮める。今回は、Kev-4B とこれまでの学習結果(第10世代まで)をそのまま引き継ぎ、実行環境だけを入れ替える。詳しい構想は 高速化構想 にある。

    遅い原因: (1) Qwen3.5 の DeltaNet と畳み込みに使う高速化ライブラリ(flash-linear-attention、causal-conv1d)が Windows では入らず、遅い標準実装で動いている。(2) 16GB での安定性を優先して、CUDA グラフを無効にしている。(3) 1手ずつ順番に問い合わせていて、まとめ処理を使っていない。

    今回の方針: 学習ループと Kev を Docker(WSL2 の Linux コンテナ、GPU あり)に移し、高速化ライブラリを入れる。CUDA グラフは無効のまま(4B と 16GB の組み合わせでは不安定になるおそれがあるため)。配信サーバーは Windows に残し、共有フォルダでつなぐ。

    高速化レポート: 何をして、どれだけ速くなったか

    #やったことねらい効果(測定値)
    1学習ループと Kev を Docker(WSL2 の Linux コンテナ)に移したWindows では入らない高速化ライブラリを使うためライブラリなしのコンテナでも、推論はほぼ同じ(下の表の「なし」)

    42 と 3 を併用—300 → 209 ms(約 30% 短縮)
    5Kev の融合カーネル(fused_qwen35)を無効化(KEV_FUSED=0)サーバーで最初の問い合わせ時に WSL ごと落ちる問題の回避安定して動くようになった(速さへの影響なし)

    まとめ: 実際のプレイ(サーバー経由、同じゲームの同じ局面120手)では、推論が中央値 430 → 318 ms(約 26% 短縮)になった。モデルの読み込みは 約 4 分半 → 約 16 秒。学習(重みの更新)の速さは、第11世代の学習段階の結果を待って追記する。

    つまずいた点: コンテナで Kev をサーバーとして動かすと、最初の問い合わせで WSL(Docker の仮想マシン)ごと落ちた。推論の計算だけを直接動かすと落ちなかったため、サーバーだけが使う経路を順に切り分けた。原因は、flash-linear-attention があると Kev が自動で有効にする独自の融合カーネル(fused_qwen35)だった。これを無効にし(KEV_FUSED=0)、高速化ライブラリそのものは使い続けている。
