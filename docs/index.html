Kev とは

Kev は、Jared Palmer 氏が公開しているオープンソースの決定モデル(decision model)だ。文章を生成する言語モデルとは違い、「状態」と「質問」を受け取って、答えの候補ごとの確率を1回の計算で返す。

できること: 1つの状態に対して、Yes/No(noul)、選択肢から1つを選ぶ(choice)、段階評価(score)の質問を、まとめて答えられる。確率は較正されていて、「どれくらい自信があるか」も読み取れる。

中身: Qwen3.5(0.8B / 4B / 9B)や Qwen3.8-27B をベースに、LoRA と、選択肢を指し示す小さな読み出し部(ポインタヘッド)を学習させている。文章を1文字ずつ生成しないので、速くて安い。

このプロジェクトでの使い方: テトリスの盤面を「状態」に、置き場所の候補を「選択肢」にして、Kev-4B に1手ずつ選ばせている。さらに、Kev に付属する学習スクリプト(kev.train)で、強化学習の結果を Kev 自身に覚えさせている。

ライセンス: Apache-2.0(ベースの Qwen3.5 も Apache-2.0)。

仕組み

Kev への問いかけ

Kev は文章を生成しない決定モデルで、状態と質問を受け取ると、選択肢ごとの確率を1回の計算で返す。テトリスでは1手ごとに、次のように問いかける。

状態: 盤面のテキスト表現、現在のミノ、次のミノ(1個)、列の高さ、穴の数

質問: 置き場所の候補(回転と列の組み合わせ、30〜40通り)から1つを選ぶ。各候補には、置いた結果の「消えるライン数・穴・最高の高さ・凸凹・最も深い井戸」を説明として付ける

方針: Kev に見せるのは現在と次のミノだけ。それより先のミノや、先読みの結果は見せない

ゲームのルール

項目ルール1(第0〜11世代)ルール2(第12世代〜)
ミノの出現盤面の上の外側から、どの列にも降りてこられる最上段の中央に出現する(本来のテトリスと同じ)
ゲームオーバー置き場所が1つもなくなったとき出現した位置で、ブロックと重なったとき
回転形の左上を基準に回し、左右1マスだけずらして試す簡易版標準の回転システム(SRS)。回転の中心と壁蹴りの表に従い、着地後の回転や T-スピンも正しく扱う
置き場所の候補回転して真下に落とす(第12世代の v3 からは滑り込みも)出現位置から左右移動・回転・1段落下でたどり着ける場所すべて

1ミノあたりの成績はルールをまたいでも比べられるが、ルール2の方が厳しい(中央が高くなると終わる)。過去の世代の録画は、記録したときのルールで再生している。

1世代の流れ(第18世代〜)

1練習試合Kev が16ゲームを打つ(4ゲーム同時、最大400手)。85%は Kev の一番の手、15%は上位3候補から探索。各局面で「先生」(2手先読みの探索)ならどう打つかも記録する
2学習先生の手を正解として Kev の LoRA とポインタヘッドを追加学習する(kev.train)。先生と Kev の手が食い違った局面を中心に、1世代あたり最大600手+直前の世代の分
3実力テストランダムなしで10ゲーム(1ゲームずつ、毎回同じブロック順、最大500手)。1ミノあたりの得点・ライン数、テトリス回数、生き残った手数で成績を出す

「先生」は人間が設計した評価式で2手先まで読むプログラム。第16世代からは、Kev はこの先生の手をまねて学んでいる(模倣学習)。第15世代までは、Kev 自身が試した手を報酬で選んで学ぶ強化学習だった。

モデルと環境の変遷

  • Kev-0.8B で開始学習前の 0.8B は、32手でゲームオーバー・0ライン(ほぼランダム)
  • Kev-4B に変更学習前の時点で平均4ライン・平均46手と、0.8B より明らかに強かった
  • Docker + 高速化ライブラリへ移行(第11世代〜)推論が約26%短縮、モデルの読み込みは約4分半 → 約16秒

    見直しの理由

    • v1 → v2: 1列消しばかりだったので、テトリスの価値を倍にし、高さの減点を外した(テトリスの準備では必然的に高く積むため)
    • v2 → v3: 10手以上の連携を学べるよう、評価を10手ウィンドウにした。滑り込み・回転入れを候補にし、穴とオーバーハングを分けて扱った
    • v3 → v4: 過去の事例(Dellacherie / BCTS、Cold Clear、CBMPI)を取り入れた。第16世代からは、報酬の調整だけでは伸びなかったため、2手先読みの先生の手をまねる模倣学習に切り替えた
    • v4 の途中調整: 「井戸を何本も残して天井まで積む」「2本井戸で塔が高くなる」「穴を放置する」負け方を見て、余分な井戸・積みすぎ・穴の放置を順に重く評価した

    • テトリス本体と Kev 向けインターフェースを作成候補ごとに結果の説明を付けて、Choice 質問として Kev に渡す
    • v1 の強化学習(第1〜8世代)練習試合 → 良かった手の学習 → 実力テスト。評価を平均ライン数から平均得点、1ミノあたりの値へ変更
    • v2(第9〜11世代、第6世代から分岐)テトリス狙いの報酬に変更
    • Docker と高速化ライブラリへ移行(第11世代〜)作業中は配信画面に「高速化改良中」を表示
    • ゲームのルールを本来のテトリスに合わせた(第12世代〜)出現位置でのゲームオーバー、SRS 回転、見えない4段、着地後15回の制限。回転は約88万通りの網羅テストで公式と一致
    • v3(第12〜13世代)10手ウィンドウ、滑り込み、穴の報酬。新ルールで伸び悩んだ
    • v4(第14世代〜)過去の事例を取り入れた報酬。第15世代までは伸び悩み
    • 先生つき学習(第16世代〜)2手先読みの先生をまねる模倣学習に切り替え、1ミノあたり 29 → 47点に急伸
    • 練習試合の並列化(第17世代〜)約2.6倍速く。実力テストは見る価値があるので1ゲームずつ(第18世代〜)

    • 模倣学習の頭打ち(第21〜22世代)第20世代(59.6点/ミノ)を親にした2世代が 51.5・47.7点と下回り、第16〜22世代は50点台前半を中心に上下していた
    • Kev-0.8B へ蒸留(第23世代、進行中)4B の第20世代が24ゲームを打ち、全局面に先生の手を付けたデータで Kev-0.8B を学習する。0.8B では CUDA グラフを有効化(試験で安定、1手 約196ms)

    今後の計画

    学習の3段階

    1強化学習(第1〜15世代)Kev 自身が試した手を、報酬で「期待より良かった」ものに絞って学んだ
    2模倣で加速(第16世代〜、4B、現在)2手先読みの先生の手をまねる。AlphaGo が最初に人間の棋譜をまねたのと同じ位置づけ
    30.8B で強化学習に戻す4B から Kev-0.8B に蒸留し、Kev 自身に「盤面の良さ」も答えさせて、その判断で先読みする自己改善(AlphaZero 型)に移る

    次にやること

    0.8B への蒸留(準備済み)

    模倣学習が頭打ちになったら、4B の最良世代に24ゲームを打たせ、全局面に先生の手を付けたデータ(これまでの先生つき世代の分と合わせて最大4,000手)で Kev-0.8B を学習させる。0.8B では CUDA グラフも有効にし、並列化の効果を大きくする。4B の最良世代に届かなければ 4B に戻す

    Kev 自身の判断で先読みする(強化学習)

    Kev に「この盤面はこの先どれくらい良いか」を段階評価で答えさせ、実際のその後の報酬で学習する。その判断を先読み探索の評価に使い、探索で選んだ手を覚えさせる。先生(人間の評価式)の上限を超えることを狙う

    v5: 局面に応じた戦い方と3手の先読み

    低いときは井戸掘り、穴があれば修復、高いときは生き残り、という切り替えを Kev にも伝える。先読みを3手目まで広げ、見えない3手目は7種類のミノそれぞれの最善手の平均で評価する

    候補: Laya

    ModernBERT ベースの軽量な決定モデル(4.2億パラメータ)。Kev と同じ API で、さらに速い。ただし読める長さが512トークンで、問いかけの作り直しが必要。0.8B の後の実験候補

    高速化

    1世代に30〜55分かかっているのを縮める。今回は、Kev-4B とこれまでの学習結果(第10世代まで)をそのまま引き継ぎ、実行環境だけを入れ替える。詳しい構想は 高速化構想 にある。

    遅い原因: (1) Qwen3.5 の DeltaNet と畳み込みに使う高速化ライブラリ(flash-linear-attention、causal-conv1d)が Windows では入らず、遅い標準実装で動いている。(2) 16GB での安定性を優先して、CUDA グラフを無効にしている。(3) 1手ずつ順番に問い合わせていて、まとめ処理を使っていない。

    今回の方針: 学習ループと Kev を Docker(WSL2 の Linux コンテナ、GPU あり)に移し、高速化ライブラリを入れる。CUDA グラフは無効のまま(4B と 16GB の組み合わせでは不安定になるおそれがあるため)。配信サーバーは Windows に残し、共有フォルダでつなぐ。

    2〜4 は、コンテナ内で第10世代のモデルに同じ問いかけ(空の盤面)を送り、2回目以降の推論時間を比べた値。1回目はコンパイルのため約 20 秒かかる。

    つまずいた点: コンテナで Kev をサーバーとして動かすと、最初の問い合わせで WSL(Docker の仮想マシン)ごと落ちた。推論の計算だけを直接動かすと落ちなかったため、サーバーだけが使う経路を順に切り分けた。原因は、flash-linear-attention があると Kev が自動で有効にする独自の融合カーネル(fused_qwen35)だった。これを無効にし(KEV_FUSED=0)、高速化ライブラリそのものは使い続けている。

    モデルの置き場所: Windows のフォルダを共有して読み込むと、起動に約4分半かかった。Docker 内部の保存領域にコピーして約16秒にした。
